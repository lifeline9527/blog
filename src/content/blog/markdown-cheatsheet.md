这份速查是写给自己的。语法都很基础，重点在"怎么写得让人愿意读"。

## 结构

一篇文章只用一个一级标题（通常就是标题本身），下面全部用二级：

```markdown
## 一节

### 一小节
```

层级不要超过三层，超过了说明这段该拆成两篇。

## 强调

- `**加粗**` 用于关键结论，一段里最多一处
- `*斜体*` 用于术语首次出现
- `~~删除线~~` 基本不用，改稿直接改

## 代码

行内代码写命令和字段名：`npm run dev`。

独立代码块一定要标语言，否则没有高亮：

````markdown
```bash
npm install
```
````

涉及多个文件的，用注释标出文件名：

```js
// src/consts.ts
export const SITE_TITLE = '我的技术笔记';
```

## 引用

引用块用来放原文、报错信息、别人的话：

> 版本号会骗人，路径不会。

## 表格

适合对比，不适合长文本。列数控制在四列以内：

| 现象 | 原因 | 处理 |
| --- | --- | --- |
| 页面 404 | `site` 配置不对 | 检查域名 |
| 白屏 | 资源路径错 | 检查 `base` |
| 样式丢失 | 构建产物没上传 | 检查输出目录 |

## 列表

无序列表用于并列，有序列表只用于有先后顺序的步骤。列表项里的句子，末尾统一不加句号——除非是完整段落。

## 图片

图片放 `src/assets/`，用相对路径引用，构建时会自动压缩成 WebP：

```markdown
![截图](../../assets/example.png)
```

alt 文本别写"图片"，写清楚图里是什么。

## 一点排版习惯

- 中英文之间加空格：`用 Astro 搭建`
- 数字和单位之间不加空格：`26GB`、`3 秒`
- 中文标点用全角，代码和命令用半角
- 段落之间空一行，不要用两个空格换行

这些规则不写进工具，写进肌肉记忆。
